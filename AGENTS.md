# GPUStack Runtime

A Python library with a unified interface for detecting accelerator (GPU/NPU) resources and
launching and managing GPU workloads on Docker, Kubernetes and Podman.

## Project Structure

- `gpustack_runtime/` — the library.
  - `detector/` — one detector per vendor (`nvidia.py`, `amd.py`, `ascend.py`, `cambricon.py`,
    `hygon.py`, `iluvatar.py`, `metax.py`, `mthreads.py`, `thead.py`), plus the `py*` packages,
    ctypes bindings to vendor management libraries (`pynvml`, `pydcmi`, `pycndev`, ...).
  - `deployer/` — one deployer per container runtime (`docker.py`, `kubernetes.py`, `podman.py`),
    `cdi/` for vendor CDI spec handling, `k8s/` for Kubernetes helpers, and `__patches__.py` for
    the vendored Podman client patch.
  - `cmds/` — CLI subcommands behind the `gpustack-runtime` entrypoint (`__main__.py`).
  - `envs.py` — environment variables; `logging.py` — logging helpers.
- `tests/gpustack_runtime/` — pytest suite mirroring the package; `detector/samples/` holds
  captured vendor-tool outputs used as fixtures.
- `docs/` — MkDocs site; `docs/modules/` is API reference rendered from docstrings by
  mkdocstrings.
- `specs/` — design records.
- `pack/` / `deploy/` — container image build and deployment manifests.

## Architecture

Detection: each vendor detector in `gpustack_runtime/detector/` probes its vendor library through
the matching `py*` binding and reports `Device`s with topology. `detector/__init__.py` owns the
registry (`_DETECTORS`) and the aggregate entry points (`supported_list()`, `detect_devices()`).

Deployment: `deployer/__init__.py` owns the registry (`_DEPLOYERS`) and picks the first available
runtime (Docker, Kubernetes, Podman). A `WorkloadPlan` describes the desired containers; the
deployer injects vendor resources (CDI devices, environment variables, mounts) and returns a
workload handle for inspect/logs/exec/delete. Shared types live in `deployer/__types__.py`,
including the `OperationError` / `UnsupportedError` error contract.

## Finding sources

- Confirm the checkout, branch and uncommitted changes before reasoning about behavior. The
  published wheel or a merged PR may describe a different revision.
- Docstrings are the usage contract: `make docs` renders them into `site/`. Specs under
  `specs/` own design rationale; current code establishes what this checkout implements. Report
  disagreement rather than silently choosing one.
- For a vendor behavior claim, read the matching `py*` binding and the detector tests under
  `tests/gpustack_runtime/detector/`; captured outputs live in `detector/samples/`.
- For a concrete error, search its stable text locally first. When it concerns an upstream
  dependency (docker, kubernetes, podman clients), check that project's issues and pinned version
  in `pyproject.toml` / `uv.lock`.

## Development

Setup is `make install` (uv sync plus pre-commit hooks). Day-to-day targets:

- `make lint` — pre-commit on all files: ruff check/format, codespell, commitizen.
- `make test` — pytest.
- `make docs` — build the MkDocs site into `site/` (git-ignored).
- `make build` — build wheel and sdist into `dist/` (git-ignored).
- `make package` — build the container image with docker buildx; `PACKAGE_PUSH=true` pushes.

`gpustack_runtime/_version.py` is generated by hatch-vcs and `_version_appendix.py` by
`make prepare`; never hand-edit either.

### Python conventions

- Prefer clarity over cleverness to simplify long-term maintenance.
- Start every package module with `from __future__ import annotations as __future_annotations__`.
- Follow the ruff configuration in `ruff.toml`; run `make lint` whenever modifying Python source.
- Type-annotate public APIs and re-export them from the package `__init__.py` (`__all__`).
- Write Google-style docstrings; they render into the published API reference.
- Handle errors explicitly. Deployers raise `OperationError` or `UnsupportedError` from
  `deployer.__types__` instead of leaking runtime-client exceptions. Detectors degrade to an
  empty result and log at debug level rather than failing on a host without that vendor.
- Keep private helpers in double-underscore modules (`__types__.py`, `__utils__.py`); import them
  through the package, not across subpackages.
- Keep concurrency simple, safe and justified; minimize mutable shared state.
- Keep comments plain and short: no emoji, no decorative symbols. State the point in words.

### Testing conventions

- pytest; tests mirror the package layout under `tests/gpustack_runtime/`.
- Never require real hardware or a real container runtime. Detector tests fake the `py*` vendor
  binding in the test module; deployer tests fake the runtime client.
- Reuse captured vendor outputs from `tests/gpustack_runtime/detector/samples/` and shared
  fixtures from `fixtures/` instead of inventing new sample data.
- Verify one behavior or contract per test; assert observable state, not implementation details.
- Keep tests deterministic and repeatable: no wall-clock, ordering or randomness dependence.
